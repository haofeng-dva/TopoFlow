# TopoFlow 产品价值数据报告

## 数据范围

- 真实运行报告：12 份。
- Gate A 有效运行：9 次。
- Gate B 有效运行：4 次。
- Gate C 有效运行：4 次。
- Gate D 有效运行：4 次。
- 数据文件：`knowledge_base/gate_runs.jsonl`。
- 汇总文件：`knowledge_base/gate_summary.json`。

当前样本量适合建立经验规则和发现工程缺陷，不足以训练统计意义上的机器学习模型。建议累计到至少 100 个不同资产后再训练参数预测器。

## 已验证价值

### 1. 自动发现不可交付 AI 网格

腾讯 Hunyuan3D 2.1 官方 AI 生成样例为 19,996 顶点、40,000 三角面、水密模型。原始模型能够显示，但不代表满足工业拓扑要求。

TopoFlow 自动发现：

- PyMeshLab 对该 GLB 出现 Windows 解码兼容问题。
- 系统自动切换 Blender QuadriFlow。
- 面密度方差从 0.346 降低到 0.170，改善约 50.9%。
- TopoStrain 仍约 68.7，高于设计阈值 40，因此 Gate A 正确阻止继续烘焙和引擎交付。

这证明产品不仅执行格式转换，还能阻止“看起来能用、实际上拓扑不达标”的 AI 模型进入生产环节。

### 2. 引擎交付验证

已验证的 Gate D 任务通过率为 4/4：

- Fox：1 个 SkinnedMesh、24 根骨骼、3 段动画。
- RiggedFigure：1 个 SkinnedMesh、19 根骨骼、1 段动画。
- DamagedHelmet：静态 Mesh、UV、材质和 Prefab。
- Torus：UV、Normal、AO、Curvature、材质和 Prefab。

Gate D 能发现重复 Editor 脚本导致的编译冲突，并在修复后验证实际导入结果，而不是仅检查文件是否存在。

### 3. 自动化效率

- Gate B 当前样本通过率：4/4。
- Gate C 当前样本通过率：4/4。
- Gate D 当前样本通过率：4/4。
- Gate A 是主要瓶颈，历史样本通过率 1/9，说明测试集包含大量三角化或未经专业拓扑处理的资产。

Gate A 的低通过率不是产品失败，而是当前输入资产质量较低且标准严格。系统没有为了提高数字而降低设计文档阈值。

## 商业价值

- 将模型检查、UV、烘焙、引擎导入和审计从多个工具合并为单一流水线。
- 在进入团结引擎前阻断高风险拓扑，减少后续动画、材质和渲染返工。
- 产出可审计的 Gate A-D JSON 报告，可用于外包验收和资产标准化。
- 支持静态模型与骨骼动画资产的不同处理路径，避免重拓扑破坏 Rig 和 Animation。
- 本地规则兜底使系统在没有 API Key 时仍可运行；LLM 仅用于增强修复建议。

## 下一阶段数据目标

- 100 个不同类别模型：角色、硬表面、道具、扫描资产、AI 生成资产。
- 每类至少 20 个样本。
- 记录修复前后 Gate 指标、耗时、面数变化和最终人工评分。
- 达到 100 个样本后训练 Gate 修复参数推荐器；在此之前继续使用可解释规则。
